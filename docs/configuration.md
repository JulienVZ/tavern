# Configuration reference

A Tavern instance is configured through environment variables only. In the reference deployment they live in `deploy/.env`, created from [`deploy/.env.example`](../deploy/.env.example) by `deploy/scripts/init.sh`.

No domain, address or secret is built into the software.

## Deployment variables (`deploy/.env`)

| Variable | Required | Default | Description |
|---|---|---|---|
| `TAVERN_DOMAIN` | yes | — | Public host name of the instance (API and gateway). What users type in the client. |
| `LIVEKIT_DOMAIN` | yes | — | Public host name of LiveKit signalling. Different from `TAVERN_DOMAIN`, same machine. |
| `CADDY_HTTP_PORT` | no | `80` | Host port for HTTP (ACME challenges and redirect to HTTPS). |
| `CADDY_HTTPS_PORT` | no | `443` | Host port for HTTPS. |
| `POSTGRES_USER` | no | `tavern` | PostgreSQL role. |
| `POSTGRES_DB` | no | `tavern` | PostgreSQL database. |
| `POSTGRES_PASSWORD` | yes | generated | **Secret.** Hexadecimal, generated by `init.sh`. |
| `TAVERN_SERVER_IMAGE` | no | built locally | Server image to run instead of building from the repository. |
| `LIVEKIT_API_KEY` | yes | generated | **Secret.** Shared by the Tavern server and LiveKit. |
| `LIVEKIT_API_SECRET` | yes | generated | **Secret.** Shared by the Tavern server and LiveKit. |
| `LIVEKIT_NODE_IP` | on a real deployment | empty | Public IPv4 address advertised to clients for media. |
| `LIVEKIT_RTC_TCP_PORT` | no | `7881` | Media over TCP. Must match `rtc.tcp_port` in `livekit.yaml`. |
| `LIVEKIT_RTC_UDP_PORT` | no | `7882` | Media over UDP (single multiplexed port). Must match `rtc.udp_port` in `livekit.yaml`. |

## Server variables

Read by the `tavern-server` binary. The compose file sets them from the variables above.

| Variable | Required | Default | Description |
|---|---|---|---|
| `TAVERN_DATABASE_URL` | yes | — | **Secret.** `postgres://user:password@host:port/database`. Never logged. |
| `TAVERN_LISTEN_ADDR` | no | `0.0.0.0:8080` | Address and port of the HTTP server. |
| `TAVERN_DB_MAX_CONNECTIONS` | no | `10` | Size of the database connection pool. |
| `TAVERN_RUN_MIGRATIONS` | no | `true` | Apply database migrations at start-up. Set to `false` to apply them yourself. |
| `TAVERN_LOG_LEVEL` | no | `info` | `error`, `warn`, `info`, `debug`, `trace`, or a `tracing` directive such as `tavern_server=debug,info`. |
| `TAVERN_LOG_FORMAT` | no | `text` | `text` or `json`. |
| `TAVERN_SOURCE_URL` | no | empty | URL of this instance's source code, shown by `GET /version`. Set it if you run modified code (AGPL). |

An empty value counts as unset. An invalid value stops the server at start-up with a message naming the variable.

## Secrets

| Secret | Generated by | Used for | If lost |
|---|---|---|---|
| `POSTGRES_PASSWORD` | `init.sh` | Database access | Reset it in PostgreSQL and in `.env`. |
| `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET` | `init.sh` | Signing voice access tokens | Generate new ones; running calls drop. |

Milestone M1 adds three more, each with a single purpose: the OPAQUE server setup (losing it invalidates every password), the dedicated MLS external sender key (see [ADR 0002](adr/0002-mls-via-openmls.md#external-sender-key-lifecycle)) and the key that encrypts TOTP secrets. All secrets are stored in `.env`, which `backup.sh` includes in every backup.

## Other files

| File | Purpose |
|---|---|
| `deploy/Caddyfile` | Reverse proxy and TLS. Created from `Caddyfile.example`. Domains come from `.env`. |
| `deploy/livekit.yaml` | LiveKit settings without secrets. Created from `livekit.yaml.example`. |
| `deploy/docker-compose.dev.yml` | Development override that publishes the server and PostgreSQL on `127.0.0.1`. Not for real instances. |

## Endpoints useful to operators

| Endpoint | Answer |
|---|---|
| `GET /health` | `200 {"status":"ok","database":"ok"}`, or `503` when the database is unreachable. |
| `GET /version` | Server version, supported gateway protocol versions, source URL. |
