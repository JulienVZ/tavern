# Configuration reference

A Tavern instance is configured through environment variables only. In the reference deployment they live in `deploy/.env`, created from [`deploy/.env.example`](../deploy/.env.example) by `deploy/scripts/init.sh`.

No domain, address or secret is built into the software.

## Deployment variables (`deploy/.env`)

| Variable | Required | Default | Description |
|---|---|---|---|
| `TAVERN_DOMAIN` | yes | — | Public host name of the instance (API and gateway). What users type in the client. |
| `LIVEKIT_DOMAIN` | yes | — | Public host name of LiveKit signalling. Different from `TAVERN_DOMAIN`, same machine. |
| `CADDY_HTTP_PORT` | no | `80` | Host port for HTTP (ACME challenges and redirect to HTTPS). |
| `CADDY_HTTPS_PORT` | no | `443` | Host port for HTTPS. |
| `POSTGRES_USER` | no | `tavern` | PostgreSQL role. |
| `POSTGRES_DB` | no | `tavern` | PostgreSQL database. |
| `POSTGRES_PASSWORD` | yes | generated | **Secret.** Hexadecimal, generated by `init.sh`. |
| `TAVERN_SERVER_IMAGE` | no | built locally | Server image to run instead of building from the repository. |
| `LIVEKIT_API_KEY` | yes | generated | **Secret.** Shared by the Tavern server and LiveKit. |
| `LIVEKIT_API_SECRET` | yes | generated | **Secret.** Shared by the Tavern server and LiveKit. |
| `LIVEKIT_NODE_IP` | on a real deployment | empty | Public IPv4 address advertised to clients for media. |
| `LIVEKIT_RTC_TCP_PORT` | no | `7881` | Media over TCP. Must match `rtc.tcp_port` in `livekit.yaml`. |
| `LIVEKIT_RTC_UDP_PORT` | no | `7882` | Media over UDP (single multiplexed port). Must match `rtc.udp_port` in `livekit.yaml`. |

## Server variables

Read by the `tavern-server` binary. The compose file sets them from the variables above.

| Variable | Required | Default | Description |
|---|---|---|---|
| `TAVERN_DATABASE_URL` | yes | — | **Secret.** `postgres://user:password@host:port/database`. Never logged. |
| `TAVERN_LISTEN_ADDR` | no | `0.0.0.0:8080` | Address and port of the HTTP server. |
| `TAVERN_DB_MAX_CONNECTIONS` | no | `10` | Size of the database connection pool. |
| `TAVERN_RUN_MIGRATIONS` | no | `true` | Apply database migrations at start-up. Set to `false` to apply them yourself. |
| `TAVERN_LOG_LEVEL` | no | `info` | `error`, `warn`, `info`, `debug`, `trace`, or a `tracing` directive such as `tavern_server=debug,info`. |
| `TAVERN_LOG_FORMAT` | no | `text` | `text` or `json`. |
| `TAVERN_BUILD_COMMIT` | no | empty | **Build time only** (Docker build argument, set by `scripts/build.sh` and by the CI): the commit the server is built from, reported by `GET /version`. Has no effect on a running server. |
| `TAVERN_SOURCE_URL` | no | empty | URL of this instance's source code, shown by `GET /version`. Set it if you run modified code (AGPL). |
| `TAVERN_SESSION_TTL_DAYS` | no | `90` | Days an unused session stays valid (1 to 3650). |
| `TAVERN_TRUST_FORWARDED_FOR` | no | `false` | Use the last `X-Forwarded-For` entry as the client address for rate limiting. The reference compose file sets it to `true` because the server is reachable through Caddy only. Leave it unset if clients can reach the server directly. |
| `TAVERN_OPAQUE_SERVER_SETUP` | yes | generated | **Secret.** See "Secrets". |
| `TAVERN_MLS_EXTERNAL_SENDER_KEY` | yes | generated | **Secret.** See "Secrets". |
| `TAVERN_TOTP_ENCRYPTION_KEY` | yes | generated | **Secret.** See "Secrets". |
| `TAVERN_HANDLE_PRIVACY_KEY` | yes | generated | **Secret.** See "Secrets". |

An empty value counts as unset. An invalid value stops the server at start-up with a message naming the variable.

## Secrets

All secrets live in `deploy/.env`. Each has a single purpose. `init.sh` generates the ones that are empty and never changes an existing one. `backup.sh` puts `.env` in every backup, next to the database dump it belongs to.

| Secret | Generated by | Used for | If lost or changed |
|---|---|---|---|
| `POSTGRES_PASSWORD` | `init.sh` | Database access | The server stops with "PostgreSQL rejected the credentials". Restore the old value. |
| `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET` | `init.sh` | Signing voice access tokens | Generate new ones; running calls drop. |
| `TAVERN_OPAQUE_SERVER_SETUP` | `tavern-server gen-secrets` | Server half of password authentication | **No user can log in with their password any more.** Each user must recover their account with their recovery key. Never regenerate it on an instance with accounts. |
| `TAVERN_MLS_EXTERNAL_SENDER_KEY` | `tavern-server gen-secrets` | Dedicated key with which the server proposes the removal of members from encrypted groups (from milestone M2). Used for nothing else. | Existing groups no longer accept the server's removal proposals until a member repairs each group. See [ADR 0002](adr/0002-mls-via-openmls.md#external-sender-key-lifecycle) for the rotation procedure. |
| `TAVERN_TOTP_ENCRYPTION_KEY` | `tavern-server gen-secrets` | Encrypting TOTP secrets in the database | Users with TOTP enabled cannot pass the second step. An administrator disables their TOTP and they set it up again. |
| `TAVERN_HANDLE_PRIVACY_KEY` | `tavern-server gen-secrets` | Deriving the decoy answers given for unknown handles, so that the server does not reveal which accounts exist | Nothing breaks. Decoy answers change, which for a short time could tell an observer who recorded the old ones that a handle does not exist. |

The server refuses to start when one of its four secrets is missing or malformed, and names the variable without printing its value.

`tavern-server gen-secrets` prints a complete fresh set as `NAME=value` lines and writes nothing. `init.sh` runs it in the server image and copies only the values that are still empty in `.env`.

## Other files

| File | Purpose |
|---|---|
| `deploy/Caddyfile` | Reverse proxy and TLS. Created from `Caddyfile.example`. Domains come from `.env`. |
| `deploy/livekit.yaml` | LiveKit settings without secrets. Created from `livekit.yaml.example`. |
| `deploy/docker-compose.dev.yml` | Development override that publishes the server and PostgreSQL on `127.0.0.1`. Enabled by `init.sh --dev`, which writes `COMPOSE_FILE=docker-compose.yml:docker-compose.dev.yml` into `.env`. Not for real instances. |

## Endpoints useful to operators

| Endpoint | Answer |
|---|---|
| `GET /health` | `200 {"status":"ok","database":"ok"}`, or `503` when the database is unreachable. |
| `GET /version` | Server version, supported gateway protocol versions, public key of the MLS external sender, source URL, and `commit`: the Git commit the server was built from, when the build recorded it. |
| `GET /v1/openapi.json` | OpenAPI description of the REST API. |

## Request log

At the `info` level the server writes one line per request (except `/health`), with four fields and nothing else:

```
INFO tavern_server::telemetry: request method=POST route=/v1/admin/users/{user_id}/totp/disable status=204 duration_ms=7
```

- `route` is the route template, never the URL: identifiers in the path and query strings are not logged. A request that matches no route is logged as `route=unmatched`.
- No client address, handle, token, header or body is logged, at any level.
- Calls to `/health` are logged at `debug` only: the container health check makes one every ten seconds.

## Server commands

| Command | Purpose |
|---|---|
| `tavern-server` | Run the server. |
| `tavern-server gen-secrets` | Print a fresh set of instance secrets. |
| `tavern-server create-admin-invite` | Print a single-use invitation code whose account becomes an administrator. |
| `tavern-server healthcheck` | Exit with status 0 when the local `/health` answers 200. |
