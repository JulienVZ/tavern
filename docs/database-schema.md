# Server database schema (M1–M4)

This is the proposed PostgreSQL schema for milestones M1 to M4. It is a design document: the real schema will arrive as sqlx migrations, milestone by milestone, and M0 ships an empty initial migration.

The point of this document is to show, column by column, that the server database holds **no plaintext content**.

## 1. Column classes

Every column belongs to one of these classes, noted in the comment next to it.

| Class | Meaning |
|---|---|
| `META` | Metadata the server is allowed to see (ids, timestamps, sizes, membership, names declared visible in the [threat model](threat-model.md)) |
| `PUB` | Public key material or signed public structures (public keys, certificates, KeyPackages, public MLS tree) |
| `HASH` | One-way hash of a secret that the server never stores in clear |
| `AUTH` | Authentication verifier that does not reveal the secret (OPAQUE record) |
| `WRAP` | Key material encrypted on the client under a key the server does not have |
| `E2EE` | End-to-end encrypted payload, opaque to the server |
| `SRV` | Secret the server must be able to use, encrypted at rest with an instance key |
| `HALF` | Server half of a client key: random, stored in clear, useless without a half the server never has ([ADR 0017](adr/0017-device-identity-and-sign-out.md)) |

There is no class for plaintext content, because there is no such column.

What is deliberately **absent** from the schema: message text, reactions, attachments' names and types, custom emojis, link previews, private group names, device names in clear, kick or ban reasons, IP addresses, user agents.

## 2. Conventions

- Primary keys are UUIDv7 (`uuid`), generated by PostgreSQL (`uuidv7()`, which requires PostgreSQL 18 or newer).
- Timestamps are `timestamptz`, set by the server.
- The table prefix `guild` designates what the UI calls a "server", to avoid confusion with the server process.
- The SQL of tables that are already implemented (M1, and in M2 `conversations`, `dm_conversations`, `mls_groups`, `mls_group_entries`, `key_packages`, `friendships`, `blocks`, `conversation_devices`, `messages`, `sent_messages` and `welcomes`) is identical to the migrations. The other tables omit `ON DELETE` rules for brevity.

## 3. M1 — accounts, devices, sessions, invitations

```sql
CREATE TABLE users (
    id                      uuid PRIMARY KEY DEFAULT uuidv7(),  -- META
    handle                  text NOT NULL UNIQUE,            -- META  visible identifier, lower case
    display_name            text NOT NULL,                   -- META  profile, visible in v1 (ADR 0008)
    is_admin                boolean NOT NULL DEFAULT false,  -- META
    opaque_suite            smallint NOT NULL,               -- META  version of the OPAQUE and Argon2id parameters
    opaque_record           bytea NOT NULL,                  -- AUTH  OPAQUE ServerRegistration
    identity_key            bytea NOT NULL,                  -- PUB   account identity key (Ed25519)
    identity_key_wrapped_pw bytea NOT NULL,                  -- WRAP  account root secret under the OPAQUE export key
    identity_key_wrapped_rk bytea NOT NULL,                  -- WRAP  account root secret under the recovery key
    totp_secret             bytea,                           -- SRV   encrypted with the instance TOTP key
    totp_enabled_at         timestamptz,                     -- META
    totp_last_step          bigint,                          -- META  last accepted time step, against replay
    storage_quota_bytes     bigint,                          -- META  NULL = instance default
    created_at              timestamptz NOT NULL DEFAULT now(), -- META
    disabled_at             timestamptz,                     -- META
    CONSTRAINT users_handle_format CHECK (handle ~ '^[a-z0-9_.]{2,32}$'),
    CONSTRAINT users_display_name_length CHECK (char_length(display_name) BETWEEN 1 AND 64)
);

CREATE TABLE totp_recovery_codes (
    user_id     uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE, -- META
    code_hash   bytea NOT NULL,                              -- HASH
    used_at     timestamptz,                                 -- META
    PRIMARY KEY (user_id, code_hash)
);

CREATE TABLE devices (
    id              uuid PRIMARY KEY DEFAULT uuidv7(),       -- META
    user_id         uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE, -- META
    signature_key   bytea NOT NULL UNIQUE,                   -- PUB   MLS leaf signature key (Ed25519)
    certificate     bytea NOT NULL,                          -- PUB   signed by the account identity key
    name_encrypted  bytea,                                   -- E2EE  readable by the user's own devices only
    platform        smallint NOT NULL,                       -- META  windows / macos / linux
    created_at      timestamptz NOT NULL DEFAULT now(),      -- META
    last_seen_at    timestamptz,                             -- META  day precision
    devices_seen_at timestamptz NOT NULL DEFAULT now(),      -- META  enrolments after this instant were not shown to this device yet
    revoked_at      timestamptz,                             -- META
    local_store_share bytea                                  -- HALF  server part of the local store key (ADR 0017); erased at revocation
);
CREATE INDEX devices_user_idx ON devices (user_id) WHERE revoked_at IS NULL;

CREATE TABLE sessions (
    id            uuid PRIMARY KEY DEFAULT uuidv7(),         -- META
    device_id     uuid NOT NULL UNIQUE REFERENCES devices(id) ON DELETE CASCADE, -- META  one session per device
    token_hash    bytea NOT NULL UNIQUE,                     -- HASH  SHA-256 of the random token
    created_at    timestamptz NOT NULL DEFAULT now(),        -- META
    last_used_at  timestamptz NOT NULL DEFAULT now(),        -- META
    expires_at    timestamptz NOT NULL,                      -- META
    revoked_at    timestamptz                                -- META
);

CREATE TABLE instance_invites (
    id           uuid PRIMARY KEY DEFAULT uuidv7(),          -- META
    code_hash    bytea NOT NULL UNIQUE,                      -- HASH  the code is shown once to the admin
    created_by   uuid REFERENCES users(id) ON DELETE SET NULL, -- META  NULL when created on the host
    grants_admin boolean NOT NULL DEFAULT false,             -- META  only for the bootstrap invite
    max_uses     integer NOT NULL DEFAULT 1,                 -- META
    uses         integer NOT NULL DEFAULT 0,                 -- META
    expires_at   timestamptz,                                -- META
    revoked_at   timestamptz,                                -- META
    created_at   timestamptz NOT NULL DEFAULT now(),         -- META
    CONSTRAINT instance_invites_uses CHECK (uses >= 0 AND uses <= max_uses AND max_uses >= 1)
);

CREATE TABLE instance_invite_uses (
    invite_id   uuid NOT NULL REFERENCES instance_invites(id) ON DELETE CASCADE, -- META
    user_id     uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE, -- META
    used_at     timestamptz NOT NULL DEFAULT now(),          -- META
    PRIMARY KEY (invite_id, user_id)
);

-- Instance-level administrative actions: who did what to whom. No free text.
CREATE TABLE admin_audit_log (
    id          uuid PRIMARY KEY DEFAULT uuidv7(),           -- META
    actor_id    uuid REFERENCES users(id) ON DELETE SET NULL, -- META  NULL for actions run on the host
    action      smallint NOT NULL,                           -- META  enum: disable TOTP, disable user, revoke invite, ...
    target_id   uuid,                                        -- META  user or invite concerned
    created_at  timestamptz NOT NULL DEFAULT now()           -- META
);
CREATE INDEX admin_audit_log_created_idx ON admin_audit_log (created_at);

-- Security-relevant events of an account, kept until each device has shown them (ADR 0016).
CREATE TABLE security_notices (
    id          uuid PRIMARY KEY DEFAULT uuidv7(),           -- META
    user_id     uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE, -- META  the account concerned
    kind        smallint NOT NULL,                           -- META  enum: TOTP disabled by an admin, password changed, ...
    created_at  timestamptz NOT NULL DEFAULT now(),          -- META
    backup_taken_at timestamptz,                             -- META  kinds 6 and 7 (instance restored) only: when the backup was taken, if known (migrations 0014, 0015)
    CHECK (backup_taken_at IS NULL OR kind IN (6, 7))
);
CREATE INDEX security_notices_user_idx ON security_notices (user_id, created_at);

-- One row per device that dismissed a notice.
CREATE TABLE security_notice_acks (
    notice_id   uuid NOT NULL REFERENCES security_notices(id) ON DELETE CASCADE, -- META
    device_id   uuid NOT NULL REFERENCES devices(id) ON DELETE CASCADE, -- META
    acked_at    timestamptz NOT NULL DEFAULT now(),          -- META
    PRIMARY KEY (notice_id, device_id)
);
```

Handles are stored in lower case; the format is enforced by a constraint, so no extension is needed.

In-flight OPAQUE state, enrolment tokens, session challenges and rate limiter counters stay in memory and are not persisted. Client IP addresses are never written to the database.

`admin_audit_log` records instance-level actions such as an administrator disabling a user's TOTP. It holds identifiers and an action code only.

`security_notices` holds what each device of an account must tell its user: TOTP disabled by an administrator (1), password changed (2), account recovered with the recovery key (3), device revoked (4), recovery key replaced (5). A row is an account, a kind and a date: no text, no device, no address. `security_notice_acks` records which devices dismissed which notice. Notices are deleted 90 days after the event, when the next one is recorded for the account ([ADR 0016](adr/0016-security-notices.md)).

Profile fields added at M5 (`bio`, `custom_status`, `avatar_blob_id`, `banner_blob_id`) are `META` in v1 and become `E2EE` if [ADR 0008](adr/0008-encrypted-profiles.md) is implemented.

## 4. M2 — KeyPackages, friends, conversations, messages

```sql
-- Implemented (task 5 of M2, migrations 0006 and 0009). The KeyPackages
-- each device keeps on the server (ADR 0019, section 3): up to 200 one-time
-- packages, each served once, and one last-resort package, served when no
-- one-time package is left and kept until the device replaces it. A served
-- one-time package keeps its row, without its bytes, until it expires: its
-- reference stays taken, so that the same package sent again is never
-- stored nor served a second time, and its leaf's encryption key: the
-- server cannot read a group's first commit, but finds in its tree the leaf
-- of the package that added each device, and checks that the Welcome is for
-- exactly those packages (migration 0011; packages uploaded before have an
-- empty key, and no first commit can add them). Public MLS data only: the private parts
-- stay on the device. A revoked device's packages are deleted with its
-- revocation.
CREATE TABLE key_packages (
    id           uuid PRIMARY KEY DEFAULT uuidv7(),          -- META
    device_id    uuid NOT NULL REFERENCES devices(id) ON DELETE CASCADE, -- META
    key_package  bytea NOT NULL,                             -- PUB   MLS KeyPackage, signed by the device
    reference    bytea NOT NULL UNIQUE,                      -- PUB   KeyPackageRef (hash)
    last_resort  boolean NOT NULL DEFAULT false,             -- META
    expires_at   timestamptz NOT NULL,                       -- META  end of the KeyPackage's lifetime
    created_at   timestamptz NOT NULL DEFAULT now(),         -- META
    served_at    timestamptz,                                -- META  when a claim first served it (migration 0009; last resorts too, migration 0013)
    leaf_key     bytea NOT NULL,                             -- PUB   encryption key of the package's leaf, kept once served (migration 0011)
    CHECK (octet_length(key_package) <= 4096),
    -- A served one-time package keeps no bytes; a last resort keeps them
    -- while it is the last resort, and once replaced, if it was served, is
    -- kept as served without them until it expires (migration 0013).
    CONSTRAINT key_packages_served CHECK (
        served_at IS NULL OR last_resort OR octet_length(key_package) = 0
    ),
    CONSTRAINT key_packages_leaf_key CHECK (octet_length(leaf_key) <= 256)
);
-- A claim serves a device's oldest one-time package first.
CREATE INDEX key_packages_device_idx ON key_packages (device_id, last_resort, created_at);
-- One last-resort package per device.
CREATE UNIQUE INDEX key_packages_last_resort_idx ON key_packages (device_id) WHERE last_resort;

-- Implemented (task 6 of M2, migration 0007). Friends and blocks (ADR
-- 0020). One row per pair of users in friendships, whatever its state: at
-- most one request per pair. A request sent to a user who blocks its sender
-- is kept, hidden from that user and shown to its sender only, so that the
-- block is not disclosed; it is deleted when the block is lifted.
CREATE TYPE friendship_status AS ENUM ('pending', 'accepted');

CREATE TABLE friendships (
    user_low      uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE, -- META  smaller id of the pair
    user_high     uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE, -- META
    status        friendship_status NOT NULL,                -- META
    requested_by  uuid NOT NULL,                             -- META  who sent the request
    hidden        boolean NOT NULL DEFAULT false,            -- META  sent to a user who blocks its sender: shown to the sender only
    created_at    timestamptz NOT NULL DEFAULT now(),        -- META
    accepted_at   timestamptz,                               -- META
    PRIMARY KEY (user_low, user_high),
    CHECK (user_low < user_high),
    CHECK (requested_by IN (user_low, user_high)),
    CHECK ((status = 'accepted') = (accepted_at IS NOT NULL)),
    CHECK (NOT hidden OR status = 'pending')
);
CREATE INDEX friendships_high_idx ON friendships (user_high);

CREATE TABLE blocks (
    blocker_id  uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE, -- META
    blocked_id  uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE, -- META
    created_at  timestamptz NOT NULL DEFAULT now(),          -- META
    PRIMARY KEY (blocker_id, blocked_id),
    CHECK (blocker_id <> blocked_id)
);
CREATE INDEX blocks_blocked_idx ON blocks (blocked_id);

-- Implemented (task 7 of M2, migration 0008). Conversations (ADR 0019,
-- section 4). One row per conversation; a DM also has its pair of users in
-- dm_conversations, unique: one DM per pair. A conversation may have no MLS
-- group yet (its creating device stopped before the first commit): any
-- active device of a participant may create it. Groups and channels come
-- with M3 and M4.
CREATE TYPE conversation_kind AS ENUM ('dm', 'group', 'text_channel', 'voice_channel');

CREATE TABLE conversations (
    id            uuid PRIMARY KEY DEFAULT uuidv7(),         -- META
    kind          conversation_kind NOT NULL,                -- META
    last_seq      bigint NOT NULL DEFAULT 0,                 -- META  last assigned sequence number
    created_by    uuid REFERENCES users(id) ON DELETE SET NULL, -- META
    created_at    timestamptz NOT NULL DEFAULT now(),        -- META
    needs_recreation boolean NOT NULL DEFAULT false,         -- META  set by a restore, or with `group_dead`: only the recreation of its group is accepted (migration 0014)
    recreated_at  timestamptz,                               -- META  last recreation of its group: a user may ask for one at most once an hour
    group_dead    boolean NOT NULL DEFAULT false,            -- META  no member of its group can commit: recreated at the next generation (migration 0017)
    CHECK (last_seq >= 0),
    CHECK (NOT group_dead OR needs_recreation)
);

CREATE TABLE dm_conversations (
    conversation_id uuid PRIMARY KEY REFERENCES conversations(id) ON DELETE CASCADE, -- META
    user_low        uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE, -- META  smaller id of the pair
    user_high       uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE, -- META
    UNIQUE (user_low, user_high),
    CHECK (user_low < user_high)
);
CREATE INDEX dm_conversations_high_idx ON dm_conversations (user_high);

-- Implemented (task 4 of M2, migration 0005). The public state of each MLS
-- group (ADR 0019, section 14): one row per group generation, and the rows
-- OpenMLS keeps for it (ratchet tree, group context, transcript hash,
-- confirmation tag, the server's own stored proposals). No secret and no
-- content: public MLS data and metadata only. The server keeps the current
-- generation of a conversation only: creating a generation deletes the
-- earlier ones in the same transaction.
--
-- conversation_id references conversations(id) ON DELETE CASCADE: the
-- foreign key is added by migration 0008, with that table.
CREATE TABLE mls_groups (
    group_id        bytea PRIMARY KEY,                       -- META  conversation id then generation, 20 bytes
    conversation_id uuid NOT NULL,                           -- META
    generation      bigint NOT NULL,                         -- META
    epoch           bigint NOT NULL,                         -- META  current epoch
    revision        bigint NOT NULL DEFAULT 0,               -- META  saves so far: a save writes only over the revision it loaded
    group_info      bytea NOT NULL,                          -- PUB   latest GroupInfo with its ratchet tree, for external commits
    updated_at      timestamptz NOT NULL DEFAULT now(),      -- META
    UNIQUE (conversation_id, generation),
    CHECK (generation BETWEEN 0 AND 4294967295),
    -- The MLS group id: the conversation id, then the generation as 4
    -- big-endian bytes (ADR 0019, section 17).
    CHECK (group_id = uuid_send(conversation_id) || substring(int8send(generation) FROM 5 FOR 4)),
    CHECK (epoch >= 1),
    CHECK (revision >= 0)
);

CREATE TABLE mls_group_entries (
    group_id  bytea NOT NULL REFERENCES mls_groups(group_id) ON DELETE CASCADE, -- META
    kind      smallint NOT NULL,                             -- META  1 tree, 2 context, 3 transcript hash, 4 tag, 5 proposal queue, 6 proposal
    key       bytea NOT NULL,                                -- PUB   empty, or a proposal reference
    value     bytea NOT NULL,                                -- PUB   public MLS state, as OpenMLS serialises it
    PRIMARY KEY (group_id, kind, key),
    CHECK (kind BETWEEN 1 AND 6)
);

-- Implemented (task 8 of M2, migration 0010). A conversation's sequence
-- (ADR 0019, sections 4 to 7 and 12): commits,
-- application messages and the server's proposals, numbered under the lock
-- of the conversation's row (conversations.last_seq), strictly increasing
-- and without gaps; who receives them; the welcomes of the devices a commit
-- adds; and the idempotency records of sent messages, which outlive them.
-- Acknowledged and expired rows are deleted by the hourly purge (task 9 of
-- M2, crates/server/src/purge.rs).

-- The devices of each conversation's group, computed by the server from the
-- merged public tree in the transaction that merges a commit, never from
-- what a client says. A device reads the sequence after joined_seq, up to
-- left_seq once it left: the commit that removed it included.
CREATE TABLE conversation_devices (
    conversation_id uuid NOT NULL REFERENCES conversations(id) ON DELETE CASCADE, -- META
    device_id       uuid NOT NULL REFERENCES devices(id) ON DELETE CASCADE, -- META
    leaf_index      integer NOT NULL,                        -- META
    joined_seq      bigint NOT NULL,                         -- META  the commit that added it
    left_seq        bigint,                                  -- META  the commit that removed it
    acked_seq       bigint NOT NULL,                         -- META  delivery cursor
    leaf_expires_at timestamptz,                             -- META  end of the lifetime of a leaf never updated (migration 0016)
    PRIMARY KEY (conversation_id, device_id),
    CHECK (leaf_index >= 0),
    CHECK (acked_seq >= joined_seq),
    CHECK (left_seq IS NULL OR left_seq >= joined_seq)
);
CREATE UNIQUE INDEX conversation_devices_leaf_idx
    ON conversation_devices (conversation_id, leaf_index) WHERE left_seq IS NULL;
CREATE INDEX conversation_devices_device_idx ON conversation_devices (device_id);

CREATE TABLE messages (
    conversation_id  uuid NOT NULL REFERENCES conversations(id) ON DELETE CASCADE, -- META
    seq              bigint NOT NULL,                        -- META
    epoch            bigint NOT NULL,                        -- META  the epoch it belongs to (a commit: the one it ends)
    kind             smallint NOT NULL,                      -- META  1 application, 2 commit, 3 proposal
    sender_device_id uuid REFERENCES devices(id) ON DELETE SET NULL, -- META  NULL for the server's proposals
    payload          bytea NOT NULL,                         -- E2EE  kind 1 (MLS PrivateMessage); PUB kinds 2 and 3 (signed PublicMessage)
    created_at       timestamptz NOT NULL DEFAULT now(),     -- META
    expires_at       timestamptz NOT NULL,                   -- META  the retention
    PRIMARY KEY (conversation_id, seq),
    CHECK (seq >= 1),
    CHECK (kind BETWEEN 1 AND 3),
    CHECK (kind <> 3 OR sender_device_id IS NULL)
);
CREATE INDEX messages_expiry_idx ON messages (expires_at);

-- Idempotent sending (ADR 0019, section 7): kept twice the retention, after
-- the message itself is gone, so that a resend always gets the original
-- acknowledgement and is never stored nor delivered twice.
CREATE TABLE sent_messages (
    device_id         uuid NOT NULL REFERENCES devices(id) ON DELETE CASCADE, -- META
    client_message_id uuid NOT NULL,                         -- META  chosen by the sending device
    conversation_id   uuid NOT NULL REFERENCES conversations(id) ON DELETE CASCADE, -- META
    seq               bigint NOT NULL,                       -- META
    sent_at           timestamptz NOT NULL,                  -- META  the acknowledgement's time
    expires_at        timestamptz NOT NULL,                  -- META  twice the retention
    PRIMARY KEY (device_id, client_message_id)
);
CREATE INDEX sent_messages_expiry_idx ON sent_messages (expires_at);

CREATE TABLE welcomes (
    id                  uuid PRIMARY KEY DEFAULT uuidv7(),   -- META
    conversation_id     uuid NOT NULL REFERENCES conversations(id) ON DELETE CASCADE, -- META
    recipient_device_id uuid NOT NULL REFERENCES devices(id) ON DELETE CASCADE, -- META
    payload             bytea NOT NULL,                      -- E2EE  MLS Welcome, encrypted to the recipient's KeyPackage
    created_at          timestamptz NOT NULL DEFAULT now(),  -- META
    expires_at          timestamptz NOT NULL,                -- META  the retention
    acked_at            timestamptz                          -- META  sent again at each connection until set
);
CREATE INDEX welcomes_recipient_idx ON welcomes (recipient_device_id) WHERE acked_at IS NULL;

-- Implemented (task 9 of M2, migration 0012). The server's removals not
-- committed yet (ADR 0019, sections 6 and 15), one per device of a
-- conversation's group. The proposals themselves are stored with the
-- group's public state (mls_group_entries). From its proposal on, the
-- device is cut off: no event of the conversation, the sequence read up to
-- the proposal and no further, nothing sent. A row goes when a merged
-- commit removes the leaf; proposal_seq moves when the server asks again
-- after an external commit.
CREATE TABLE pending_removals (
    conversation_id uuid NOT NULL REFERENCES conversations(id) ON DELETE CASCADE, -- META
    device_id       uuid NOT NULL REFERENCES devices(id) ON DELETE CASCADE, -- META
    leaf_index      integer NOT NULL,                        -- META
    proposal_seq    bigint NOT NULL,                         -- META  sequence number of the proposal message
    created_at      timestamptz NOT NULL DEFAULT now(),      -- META
    PRIMARY KEY (conversation_id, device_id),
    CHECK (leaf_index >= 0),
    CHECK (proposal_seq >= 1)
);
CREATE UNIQUE INDEX pending_removals_leaf_idx ON pending_removals (conversation_id, leaf_index);
CREATE INDEX pending_removals_device_idx ON pending_removals (device_id);
```

Commits and proposals are `PUB`: they are signed but not encrypted, and contain public keys and membership changes only. Their path secrets are HPKE-encrypted to members inside the commit.

```sql
-- Implemented (task 9b of M2, migration 0014). A restored backup (ADR 0019,
-- sections 15 and 17). One row. restore.sh raises the generation and
-- records the backup's date; the server raises it too when its marker
-- (TAVERN_DATA_DIR/instance-marker, outside the database) shows the
-- database behind. At start-up the server handles a generation once, in one
-- transaction: every session revoked, the notice for every account, every
-- one-time KeyPackage deleted, every invitation still valid revoked, every
-- conversation to recreate with its numbering moved on by 2^32; the
-- generation is marked handled at its end.
CREATE TABLE instance_state (
    id                 boolean PRIMARY KEY DEFAULT true,     -- META  a single row
    instance_id        uuid NOT NULL DEFAULT gen_random_uuid(), -- META  names this database in the server's marker
    generation         bigint NOT NULL DEFAULT 0,            -- META  raised by each restore, announced in Ready
    handled_generation bigint NOT NULL DEFAULT 0,            -- META  the last generation handled at start-up
    backup_taken_at    timestamptz,                          -- META  when the restored backup was taken, if known
    alive_at           timestamptz,                          -- META  the server's last record of a change, at most a few seconds old
    CHECK (id),
    CHECK (handled_generation BETWEEN 0 AND generation)
);

-- Advanced by every statement that writes to any other table (trigger
-- instance_changed, FOR EACH STATEMENT): the marker records its value, and
-- a database restored from a backup has it behind. Not transactional, so no
-- write waits for another. Every table added later gets the trigger in its
-- migration (tests/schema.rs checks it).
CREATE SEQUENCE instance_changes AS bigint;
```

```sql
CREATE TABLE group_conversations (

);

CREATE TABLE group_members (
    conversation_id uuid NOT NULL REFERENCES conversations(id), -- META
```

A private group's name and icon are sent as application messages and stored only on devices. There is no column for them.

## 6. M4 — servers, channels, roles, moderation

```sql
CREATE TABLE guilds (
    id          uuid PRIMARY KEY,                            -- META
    name        text NOT NULL,                               -- META  visible in v1
    owner_id    uuid NOT NULL REFERENCES users(id),          -- META
    created_at  timestamptz NOT NULL DEFAULT now()           -- META
);

CREATE TABLE guild_members (
    guild_id    uuid NOT NULL REFERENCES guilds(id),         -- META
    user_id     uuid NOT NULL REFERENCES users(id),          -- META
    nickname    text,                                        -- META  profile-like, visible in v1
    joined_at   timestamptz NOT NULL DEFAULT now(),          -- META
    PRIMARY KEY (guild_id, user_id)
);

CREATE TABLE roles (
    id           uuid PRIMARY KEY,                           -- META
    guild_id     uuid NOT NULL REFERENCES guilds(id),        -- META
    name         text NOT NULL,                              -- META  visible in v1
    color        integer,                                    -- META
    position     integer NOT NULL,                           -- META
    permissions  bigint NOT NULL DEFAULT 0,                  -- META  bit set
    is_default   boolean NOT NULL DEFAULT false              -- META  the "everyone" role
);

CREATE TABLE member_roles (
    guild_id  uuid NOT NULL,                                 -- META
    user_id   uuid NOT NULL,                                 -- META
    role_id   uuid NOT NULL REFERENCES roles(id),            -- META
    PRIMARY KEY (guild_id, user_id, role_id),
    FOREIGN KEY (guild_id, user_id) REFERENCES guild_members (guild_id, user_id)
);

CREATE TABLE categories (
    id        uuid PRIMARY KEY,                              -- META
    guild_id  uuid NOT NULL REFERENCES guilds(id),           -- META
    name      text NOT NULL,                                 -- META  visible in v1
    position  integer NOT NULL                               -- META
);

-- A channel is a conversation (text_channel or voice_channel) placed in a guild.
CREATE TABLE channels (
    conversation_id uuid PRIMARY KEY REFERENCES conversations(id), -- META
    guild_id        uuid NOT NULL REFERENCES guilds(id),     -- META
    category_id     uuid REFERENCES categories(id),          -- META
    name            text NOT NULL,                           -- META  visible in v1
    position        integer NOT NULL                         -- META
);

CREATE TABLE channel_overwrites (
    channel_id   uuid NOT NULL REFERENCES channels(conversation_id), -- META
    target_kind  smallint NOT NULL,                          -- META  1 role, 2 member
    target_id    uuid NOT NULL,                              -- META
    allow        bigint NOT NULL DEFAULT 0,                  -- META
    deny         bigint NOT NULL DEFAULT 0,                  -- META
    PRIMARY KEY (channel_id, target_kind, target_id)
);

CREATE TABLE guild_invites (
    id          uuid PRIMARY KEY,                            -- META
    guild_id    uuid NOT NULL REFERENCES guilds(id),         -- META
    code_hash   bytea NOT NULL UNIQUE,                       -- HASH
    created_by  uuid NOT NULL REFERENCES users(id),          -- META
    max_uses    integer,                                     -- META
    uses        integer NOT NULL DEFAULT 0,                  -- META
    expires_at  timestamptz,                                 -- META
    revoked_at  timestamptz,                                 -- META
    created_at  timestamptz NOT NULL DEFAULT now()           -- META
);

CREATE TABLE guild_bans (
    guild_id    uuid NOT NULL REFERENCES guilds(id),         -- META
    user_id     uuid NOT NULL REFERENCES users(id),          -- META
    banned_by   uuid NOT NULL REFERENCES users(id),          -- META
    created_at  timestamptz NOT NULL DEFAULT now(),          -- META
    PRIMARY KEY (guild_id, user_id)
);

-- Who did what to whom. No free text.
CREATE TABLE guild_audit_log (
    id          uuid PRIMARY KEY,                            -- META
    guild_id    uuid NOT NULL REFERENCES guilds(id),         -- META
    actor_id    uuid NOT NULL REFERENCES users(id),          -- META
    action      smallint NOT NULL,                           -- META  enum: kick, ban, role change, ...
    target_id   uuid,                                        -- META
    created_at  timestamptz NOT NULL DEFAULT now()           -- META
);
```

Channel topics, if added, are sent as application messages in the channel, like private group names. Ban reasons are sent as application messages to the remaining members and are not stored by the server.

## 7. How this is checked

- At M2, the "two clients" integration test sends known plaintext markers through a DM, then dumps every `text` and `bytea` column of the database and asserts that no marker appears.
- A schema test (`crates/server/tests/schema.rs`) lists the columns of every table in the database and fails if one is not classified in this document, or if this document describes a column that an implemented table does not have. A new column cannot be added without deciding what it holds.
- The `messages` and `welcomes` tables are queues. Their size stays bounded by the acknowledgement and retention rules in the [protocol](protocol.md#7-limits).
