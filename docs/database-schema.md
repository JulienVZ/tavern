# Server database schema (M1–M4)

This is the proposed PostgreSQL schema for milestones M1 to M4. It is a design document: the real schema will arrive as sqlx migrations, milestone by milestone, and M0 ships an empty initial migration.

The point of this document is to show, column by column, that the server database holds **no plaintext content**.

## 1. Column classes

Every column belongs to one of these classes, noted in the comment next to it.

| Class | Meaning |
|---|---|
| `META` | Metadata the server is allowed to see (ids, timestamps, sizes, membership, names declared visible in the [threat model](threat-model.md)) |
| `PUB` | Public key material or signed public structures (public keys, certificates, KeyPackages, public MLS tree) |
| `HASH` | One-way hash of a secret that the server never stores in clear |
| `AUTH` | Authentication verifier that does not reveal the secret (OPAQUE record) |
| `WRAP` | Key material encrypted on the client under a key the server does not have |
| `E2EE` | End-to-end encrypted payload, opaque to the server |
| `SRV` | Secret the server must be able to use, encrypted at rest with an instance key |
| `HALF` | Server half of a client key: random, stored in clear, useless without a half the server never has ([ADR 0017](adr/0017-device-identity-and-sign-out.md)) |

There is no class for plaintext content, because there is no such column.

What is deliberately **absent** from the schema: message text, reactions, attachments' names and types, custom emojis, link previews, private group names, device names in clear, kick or ban reasons, IP addresses, user agents.

## 2. Conventions

- Primary keys are UUIDv7 (`uuid`), generated by PostgreSQL (`uuidv7()`, which requires PostgreSQL 18 or newer).
- Timestamps are `timestamptz`, set by the server.
- The table prefix `guild` designates what the UI calls a "server", to avoid confusion with the server process.
- The SQL of sections that are already implemented (M1) is identical to the migrations. Later sections omit `ON DELETE` rules for brevity.

## 3. M1 — accounts, devices, sessions, invitations

```sql
CREATE TABLE users (
    id                      uuid PRIMARY KEY DEFAULT uuidv7(),  -- META
    handle                  text NOT NULL UNIQUE,            -- META  visible identifier, lower case
    display_name            text NOT NULL,                   -- META  profile, visible in v1 (ADR 0008)
    is_admin                boolean NOT NULL DEFAULT false,  -- META
    opaque_suite            smallint NOT NULL,               -- META  version of the OPAQUE and Argon2id parameters
    opaque_record           bytea NOT NULL,                  -- AUTH  OPAQUE ServerRegistration
    identity_key            bytea NOT NULL,                  -- PUB   account identity key (Ed25519)
    identity_key_wrapped_pw bytea NOT NULL,                  -- WRAP  account root secret under the OPAQUE export key
    identity_key_wrapped_rk bytea NOT NULL,                  -- WRAP  account root secret under the recovery key
    totp_secret             bytea,                           -- SRV   encrypted with the instance TOTP key
    totp_enabled_at         timestamptz,                     -- META
    totp_last_step          bigint,                          -- META  last accepted time step, against replay
    storage_quota_bytes     bigint,                          -- META  NULL = instance default
    created_at              timestamptz NOT NULL DEFAULT now(), -- META
    disabled_at             timestamptz,                     -- META
    CONSTRAINT users_handle_format CHECK (handle ~ '^[a-z0-9_.]{2,32}$'),
    CONSTRAINT users_display_name_length CHECK (char_length(display_name) BETWEEN 1 AND 64)
);

CREATE TABLE totp_recovery_codes (
    user_id     uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE, -- META
    code_hash   bytea NOT NULL,                              -- HASH
    used_at     timestamptz,                                 -- META
    PRIMARY KEY (user_id, code_hash)
);

CREATE TABLE devices (
    id              uuid PRIMARY KEY DEFAULT uuidv7(),       -- META
    user_id         uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE, -- META
    signature_key   bytea NOT NULL UNIQUE,                   -- PUB   MLS leaf signature key (Ed25519)
    certificate     bytea NOT NULL,                          -- PUB   signed by the account identity key
    name_encrypted  bytea,                                   -- E2EE  readable by the user's own devices only
    platform        smallint NOT NULL,                       -- META  windows / macos / linux
    created_at      timestamptz NOT NULL DEFAULT now(),      -- META
    last_seen_at    timestamptz,                             -- META  day precision
    devices_seen_at timestamptz NOT NULL DEFAULT now(),      -- META  enrolments after this instant were not shown to this device yet
    revoked_at      timestamptz,                             -- META
    local_store_share bytea                                  -- HALF  server part of the local store key (ADR 0017); erased at revocation
);
CREATE INDEX devices_user_idx ON devices (user_id) WHERE revoked_at IS NULL;

CREATE TABLE sessions (
    id            uuid PRIMARY KEY DEFAULT uuidv7(),         -- META
    device_id     uuid NOT NULL UNIQUE REFERENCES devices(id) ON DELETE CASCADE, -- META  one session per device
    token_hash    bytea NOT NULL UNIQUE,                     -- HASH  SHA-256 of the random token
    created_at    timestamptz NOT NULL DEFAULT now(),        -- META
    last_used_at  timestamptz NOT NULL DEFAULT now(),        -- META
    expires_at    timestamptz NOT NULL,                      -- META
    revoked_at    timestamptz                                -- META
);

CREATE TABLE instance_invites (
    id           uuid PRIMARY KEY DEFAULT uuidv7(),          -- META
    code_hash    bytea NOT NULL UNIQUE,                      -- HASH  the code is shown once to the admin
    created_by   uuid REFERENCES users(id) ON DELETE SET NULL, -- META  NULL when created on the host
    grants_admin boolean NOT NULL DEFAULT false,             -- META  only for the bootstrap invite
    max_uses     integer NOT NULL DEFAULT 1,                 -- META
    uses         integer NOT NULL DEFAULT 0,                 -- META
    expires_at   timestamptz,                                -- META
    revoked_at   timestamptz,                                -- META
    created_at   timestamptz NOT NULL DEFAULT now(),         -- META
    CONSTRAINT instance_invites_uses CHECK (uses >= 0 AND uses <= max_uses AND max_uses >= 1)
);

CREATE TABLE instance_invite_uses (
    invite_id   uuid NOT NULL REFERENCES instance_invites(id) ON DELETE CASCADE, -- META
    user_id     uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE, -- META
    used_at     timestamptz NOT NULL DEFAULT now(),          -- META
    PRIMARY KEY (invite_id, user_id)
);

-- Instance-level administrative actions: who did what to whom. No free text.
CREATE TABLE admin_audit_log (
    id          uuid PRIMARY KEY DEFAULT uuidv7(),           -- META
    actor_id    uuid REFERENCES users(id) ON DELETE SET NULL, -- META  NULL for actions run on the host
    action      smallint NOT NULL,                           -- META  enum: disable TOTP, disable user, revoke invite, ...
    target_id   uuid,                                        -- META  user or invite concerned
    created_at  timestamptz NOT NULL DEFAULT now()           -- META
);
CREATE INDEX admin_audit_log_created_idx ON admin_audit_log (created_at);

-- Security-relevant events of an account, kept until each device has shown them (ADR 0016).
CREATE TABLE security_notices (
    id          uuid PRIMARY KEY DEFAULT uuidv7(),           -- META
    user_id     uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE, -- META  the account concerned
    kind        smallint NOT NULL,                           -- META  enum: TOTP disabled by an admin, password changed, ...
    created_at  timestamptz NOT NULL DEFAULT now()           -- META
);
CREATE INDEX security_notices_user_idx ON security_notices (user_id, created_at);

-- One row per device that dismissed a notice.
CREATE TABLE security_notice_acks (
    notice_id   uuid NOT NULL REFERENCES security_notices(id) ON DELETE CASCADE, -- META
    device_id   uuid NOT NULL REFERENCES devices(id) ON DELETE CASCADE, -- META
    acked_at    timestamptz NOT NULL DEFAULT now(),          -- META
    PRIMARY KEY (notice_id, device_id)
);
```

Handles are stored in lower case; the format is enforced by a constraint, so no extension is needed.

In-flight OPAQUE state, enrolment tokens, session challenges and rate limiter counters stay in memory and are not persisted. Client IP addresses are never written to the database.

`admin_audit_log` records instance-level actions such as an administrator disabling a user's TOTP. It holds identifiers and an action code only.

`security_notices` holds what each device of an account must tell its user: TOTP disabled by an administrator (1), password changed (2), account recovered with the recovery key (3), device revoked (4), recovery key replaced (5). A row is an account, a kind and a date: no text, no device, no address. `security_notice_acks` records which devices dismissed which notice. Notices are deleted 90 days after the event, when the next one is recorded for the account ([ADR 0016](adr/0016-security-notices.md)).

Profile fields added at M5 (`bio`, `custom_status`, `avatar_blob_id`, `banner_blob_id`) are `META` in v1 and become `E2EE` if [ADR 0008](adr/0008-encrypted-profiles.md) is implemented.

## 4. M2 — KeyPackages, friends, conversations, messages

```sql
CREATE TABLE key_packages (
    id            uuid PRIMARY KEY,                          -- META
    device_id     uuid NOT NULL REFERENCES devices(id),      -- META
    key_package   bytea NOT NULL,                            -- PUB   MLS KeyPackage, signed by the device
    reference     bytea NOT NULL UNIQUE,                     -- PUB   KeyPackageRef (hash)
    last_resort   boolean NOT NULL DEFAULT false,            -- META
    expires_at    timestamptz NOT NULL,                      -- META  from the KeyPackage lifetime
    created_at    timestamptz NOT NULL DEFAULT now()         -- META
);
CREATE INDEX key_packages_device_idx ON key_packages (device_id, last_resort);

CREATE TYPE friendship_status AS ENUM ('pending', 'accepted');

CREATE TABLE friendships (
    user_low      uuid NOT NULL REFERENCES users(id),        -- META  smaller id of the pair
    user_high     uuid NOT NULL REFERENCES users(id),        -- META
    status        friendship_status NOT NULL,                -- META
    requested_by  uuid NOT NULL REFERENCES users(id),        -- META
    created_at    timestamptz NOT NULL DEFAULT now(),        -- META
    accepted_at   timestamptz,                               -- META
    PRIMARY KEY (user_low, user_high),
    CHECK (user_low < user_high)
);

CREATE TABLE blocks (
    blocker_id  uuid NOT NULL REFERENCES users(id),          -- META
    blocked_id  uuid NOT NULL REFERENCES users(id),          -- META
    created_at  timestamptz NOT NULL DEFAULT now(),          -- META
    PRIMARY KEY (blocker_id, blocked_id)
);

CREATE TYPE conversation_kind AS ENUM ('dm', 'group', 'text_channel', 'voice_channel');

-- One row per MLS group. The id is also the MLS group id.
CREATE TABLE conversations (
    id            uuid PRIMARY KEY,                          -- META
    kind          conversation_kind NOT NULL,                -- META
    epoch         bigint NOT NULL DEFAULT 0,                 -- META  current MLS epoch (compare-and-swap target)
    last_seq      bigint NOT NULL DEFAULT 0,                 -- META  last assigned sequence number
    public_state  bytea,                                     -- PUB   public MLS group state: tree and context, no secrets
    group_info    bytea,                                     -- PUB   latest GroupInfo, for external commits
    created_by    uuid REFERENCES users(id),                 -- META
    created_at    timestamptz NOT NULL DEFAULT now()         -- META
);

CREATE TABLE dm_conversations (
    conversation_id uuid PRIMARY KEY REFERENCES conversations(id), -- META
    user_low        uuid NOT NULL REFERENCES users(id),      -- META
    user_high       uuid NOT NULL REFERENCES users(id),      -- META
    UNIQUE (user_low, user_high),
    CHECK (user_low < user_high)
);

-- Leaves of each group, mirrored from the public MLS tree for routing.
CREATE TABLE conversation_devices (
    conversation_id   uuid NOT NULL REFERENCES conversations(id), -- META
    device_id         uuid NOT NULL REFERENCES devices(id),  -- META
    leaf_index        integer NOT NULL,                      -- META
    added_epoch       bigint NOT NULL,                       -- META
    acked_seq         bigint NOT NULL DEFAULT 0,             -- META  delivery cursor
    delivery_blocked_at timestamptz,                         -- META  set at kick time, before the Remove is committed
    PRIMARY KEY (conversation_id, device_id),
    UNIQUE (conversation_id, leaf_index)
);

-- External Remove proposals issued by the server and not yet committed.
CREATE TABLE pending_removals (
    conversation_id uuid NOT NULL REFERENCES conversations(id), -- META
    leaf_index      integer NOT NULL,                        -- META
    proposal_seq    bigint NOT NULL,                         -- META  sequence number of the proposal message
    created_at      timestamptz NOT NULL DEFAULT now(),      -- META
    PRIMARY KEY (conversation_id, leaf_index)
);

-- Ciphertext queue. Rows are deleted once acknowledged by every recipient
-- device or when expires_at passes.
CREATE TABLE messages (
    conversation_id   uuid NOT NULL REFERENCES conversations(id), -- META
    seq               bigint NOT NULL,                       -- META
    epoch             bigint NOT NULL,                       -- META
    kind              smallint NOT NULL,                     -- META  1 application, 2 commit, 3 proposal
    sender_device_id  uuid REFERENCES devices(id),           -- META  NULL for server-issued proposals
    client_message_id uuid,                                  -- META  idempotency key
    payload           bytea NOT NULL,                        -- E2EE  for kind 1 (MLS PrivateMessage);
                                                             -- PUB   for kinds 2 and 3 (signed MLS PublicMessage)
    payload_size      integer NOT NULL,                      -- META
    created_at        timestamptz NOT NULL DEFAULT now(),    -- META
    expires_at        timestamptz NOT NULL,                  -- META
    PRIMARY KEY (conversation_id, seq),
    UNIQUE (sender_device_id, client_message_id)
);
CREATE INDEX messages_expiry_idx ON messages (expires_at);

CREATE TABLE welcomes (
    id                  uuid PRIMARY KEY,                    -- META
    conversation_id     uuid NOT NULL REFERENCES conversations(id), -- META
    recipient_device_id uuid NOT NULL REFERENCES devices(id), -- META
    payload             bytea NOT NULL,                      -- E2EE  MLS Welcome, encrypted to the recipient's KeyPackage
    created_at          timestamptz NOT NULL DEFAULT now()   -- META
);
CREATE INDEX welcomes_recipient_idx ON welcomes (recipient_device_id);
```

Commits and proposals are `PUB`: they are signed but not encrypted, and contain public keys and membership changes only. Their path secrets are HPKE-encrypted to members inside the commit.

## 5. M3 — private groups

```sql
CREATE TABLE group_conversations (
    conversation_id uuid PRIMARY KEY REFERENCES conversations(id), -- META
    owner_id        uuid NOT NULL REFERENCES users(id)       -- META
);

CREATE TABLE group_members (
    conversation_id uuid NOT NULL REFERENCES conversations(id), -- META
    user_id         uuid NOT NULL REFERENCES users(id),      -- META
    added_by        uuid REFERENCES users(id),               -- META
    joined_at       timestamptz NOT NULL DEFAULT now(),      -- META
    PRIMARY KEY (conversation_id, user_id)
);
```

A private group's name and icon are sent as application messages and stored only on devices. There is no column for them.

## 6. M4 — servers, channels, roles, moderation

```sql
CREATE TABLE guilds (
    id          uuid PRIMARY KEY,                            -- META
    name        text NOT NULL,                               -- META  visible in v1
    owner_id    uuid NOT NULL REFERENCES users(id),          -- META
    created_at  timestamptz NOT NULL DEFAULT now()           -- META
);

CREATE TABLE guild_members (
    guild_id    uuid NOT NULL REFERENCES guilds(id),         -- META
    user_id     uuid NOT NULL REFERENCES users(id),          -- META
    nickname    text,                                        -- META  profile-like, visible in v1
    joined_at   timestamptz NOT NULL DEFAULT now(),          -- META
    PRIMARY KEY (guild_id, user_id)
);

CREATE TABLE roles (
    id           uuid PRIMARY KEY,                           -- META
    guild_id     uuid NOT NULL REFERENCES guilds(id),        -- META
    name         text NOT NULL,                              -- META  visible in v1
    color        integer,                                    -- META
    position     integer NOT NULL,                           -- META
    permissions  bigint NOT NULL DEFAULT 0,                  -- META  bit set
    is_default   boolean NOT NULL DEFAULT false              -- META  the "everyone" role
);

CREATE TABLE member_roles (
    guild_id  uuid NOT NULL,                                 -- META
    user_id   uuid NOT NULL,                                 -- META
    role_id   uuid NOT NULL REFERENCES roles(id),            -- META
    PRIMARY KEY (guild_id, user_id, role_id),
    FOREIGN KEY (guild_id, user_id) REFERENCES guild_members (guild_id, user_id)
);

CREATE TABLE categories (
    id        uuid PRIMARY KEY,                              -- META
    guild_id  uuid NOT NULL REFERENCES guilds(id),           -- META
    name      text NOT NULL,                                 -- META  visible in v1
    position  integer NOT NULL                               -- META
);

-- A channel is a conversation (text_channel or voice_channel) placed in a guild.
CREATE TABLE channels (
    conversation_id uuid PRIMARY KEY REFERENCES conversations(id), -- META
    guild_id        uuid NOT NULL REFERENCES guilds(id),     -- META
    category_id     uuid REFERENCES categories(id),          -- META
    name            text NOT NULL,                           -- META  visible in v1
    position        integer NOT NULL                         -- META
);

CREATE TABLE channel_overwrites (
    channel_id   uuid NOT NULL REFERENCES channels(conversation_id), -- META
    target_kind  smallint NOT NULL,                          -- META  1 role, 2 member
    target_id    uuid NOT NULL,                              -- META
    allow        bigint NOT NULL DEFAULT 0,                  -- META
    deny         bigint NOT NULL DEFAULT 0,                  -- META
    PRIMARY KEY (channel_id, target_kind, target_id)
);

CREATE TABLE guild_invites (
    id          uuid PRIMARY KEY,                            -- META
    guild_id    uuid NOT NULL REFERENCES guilds(id),         -- META
    code_hash   bytea NOT NULL UNIQUE,                       -- HASH
    created_by  uuid NOT NULL REFERENCES users(id),          -- META
    max_uses    integer,                                     -- META
    uses        integer NOT NULL DEFAULT 0,                  -- META
    expires_at  timestamptz,                                 -- META
    revoked_at  timestamptz,                                 -- META
    created_at  timestamptz NOT NULL DEFAULT now()           -- META
);

CREATE TABLE guild_bans (
    guild_id    uuid NOT NULL REFERENCES guilds(id),         -- META
    user_id     uuid NOT NULL REFERENCES users(id),          -- META
    banned_by   uuid NOT NULL REFERENCES users(id),          -- META
    created_at  timestamptz NOT NULL DEFAULT now(),          -- META
    PRIMARY KEY (guild_id, user_id)
);

-- Who did what to whom. No free text.
CREATE TABLE guild_audit_log (
    id          uuid PRIMARY KEY,                            -- META
    guild_id    uuid NOT NULL REFERENCES guilds(id),         -- META
    actor_id    uuid NOT NULL REFERENCES users(id),          -- META
    action      smallint NOT NULL,                           -- META  enum: kick, ban, role change, ...
    target_id   uuid,                                        -- META
    created_at  timestamptz NOT NULL DEFAULT now()           -- META
);
```

Channel topics, if added, are sent as application messages in the channel, like private group names. Ban reasons are sent as application messages to the remaining members and are not stored by the server.

## 7. How this is checked

- At M2, the "two clients" integration test sends known plaintext markers through a DM, then dumps every `text` and `bytea` column of the database and asserts that no marker appears.
- A schema test (`crates/server/tests/schema.rs`) lists the columns of every table in the database and fails if one is not classified in this document, or if this document describes a column that an implemented table does not have. A new column cannot be added without deciding what it holds.
- The `messages` and `welcomes` tables are queues. Their size stays bounded by the acknowledgement and retention rules in the [protocol](protocol.md#7-limits).
